2. Python 프로그래밍 기초

터미널에서 코드를 실행하는 방법과, Windows 환경에서 자주 막히는 지점을 직접 해결해 보았다.

main.py 구조 이해

  • input()으로 사용자 이름을 받고, print()와 f-string으로 Hello, 문유빈! 반갑습니다 형태의 문장을 출력한다.
  • 프로그램은 위에서 아래로 순서대로 실행되며, input()이 있으면 사용자가 Enter를 누를 때까지 다음 줄로 넘어가지 않는다.

실행 환경 문제 해결

  • 처음 실행 시 Python was not found 오류가 발생했다. PC에 Python이 없고, Windows Store용 가짜 python.exe만 연결되어 있었기 때문이다.
  • winget으로 Python 3.12를 설치하고, 프로젝트 .vscode/settings.json에 Python 경로를 넣어 Cursor 터미널에서도 인식되게 했다.
  • 예전에 연 터미널은 PATH가 갱신되지 않을 수 있으므로, 터미널을 새로 연 뒤 python main.py로 실행해야 한다는 점을 배웠다.

3. 데이터 파일과 마케팅 활용

CSV 데이터의 역할과, 고객 데이터를 바탕으로 메시지를 작성하는 흐름을 익혔다.

leads.csv 이해

  • CSV는 이름·이메일·관심분야처럼 표 형태의 데이터를 담는 파일이며, Excel에서도 열 수 있다.
  • python leads.csv처럼 실행할 수 없다. 분석하려면 Python 스크립트(.py)가 데이터를 읽어 처리해야 한다.
  • 실습 파일에는 1~5줄은 고객 데이터, 6줄 이후는 이메일 검증·관심분야 집계 코드가 섞여 있어, 데이터와 코드를 파일로 분리하는 것이 올바른 구조임을 알게 되었다.

데이터 기반 콘텐츠 작성

  • 관심분야가 「로봇」인 고객(김나래, 최영희)을 기준으로, 톤이 다른 이메일 뉴스레터 문구 3종(친근함 / 비즈니스 / 호기심 자극)을 작성해 보았다.
  • 같은 데이터라도 누구에게, 어떤 목적으로 보내는지에 따라 문장 스타일이 달라져야 한다는 점을 체감했다.
  • 이메일 주소 오타(예: naㅁver.com)처럼 데이터 품질 문제도 함께 점검해야 발송 실수를 줄일 수 있다.

4. 웹 페이지 제작 (HTML · CSS)

정적 웹 페이지의 구조, 스타일, 디자인 시스템 적용, 그리고 Cursor 모드별 활용을 실습했다.

HTML/CSS 기본 개념

  • HTML은 제목·문단·버튼처럼 무엇을 보여줄지 정하고, <style> 안의 CSS는 어떻게 보일지(색, 크기, 간격)를 정한다.
  • <style> 내용은 화면에 글로 나오지 않고, 브라우저가 읽어 전체 페이지 디자인에 적용한다.

index.html 개선

  • 상단 네비게이션에 네이버 스타일 검색창을 추가했다. 흰 입력창, #03C75A 검색 버튼, 제출 시 네이버 검색 결과로 이동한다.
  • Kinetic Typography 디자인을 적용했다. 큰 제목(clamp), 무한 마퀴, 스크롤 시 겹치는 스티키 카드, 호버 시 네이버 그린으로 색이 반전되는 카드 등으로 페이지에 동적인 느낌을 주었다.
  • 의도적으로 숨겨 둔 Debug 실습용 버그(제목 글자색 = 배경색)를 통해, Debug 모드로 문제를 찾아 고치는 연습도 이어질 수 있게 했다.

lecture.html 신규 제작

  • AI 마케팅 강의 「전략은 AI가, 판단은 내가」 소개 페이지를 새로 만들었다.
  • 강의 특징 3가지, 수강 신청 버튼, 밝고 단정한 레이아웃으로 랜딩 페이지의 기본 구성을 익혔다.

5. Cursor IDE와 MCP 연동

AI 도구를 외부 시스템(위키, 사내 MCP)과 연결하는 설정 방법과 오류 대응을 배웠다.

Cursor 4가지 모드

  • Ask — 코드·개념 질문 (예: style 태그 역할)
  • Plan — 수정 전 계획 수립 (예: 네이버 검색창 추가 계획)
  • Agent — 파일 수정·생성을 AI에게 맡김 (예: index.html 리디자인, lecture.html 생성)
  • Debug — 숨은 버그·오류 원인 찾기 (예: MCP JSON 오류, 글자색 버그)

MCP 설정 (mcp.json)

서버 역할 학습 내용
mcp-works 사내 HTTP MCP 사내망·VPN 환경에서만 연결 가능함을 확인
BA 사내 SSE MCP SSE 방식 서버는 type: sse 지정이 필요함
mcp-atlassian Confluence 위키 uvx로 실행, Windows 전체 경로·토큰·SSL 설정
  • 설정 파일에 잘못된 따옴표(곱따옴표)가 있으면 JSON 전체가 깨져 MCP가 모두 실패할 수 있다.
  • macOS용 uvx 경로는 Windows에서 동작하지 않으므로, OS에 맞는 실행 경로를 써야 한다.
  • 로그를 보면 일부 서버는 연결되고 일부는 fetch failed인 경우가 많아, 네트워크·JSON·실행 경로를 순서대로 점검해야 한다.

6. 오늘의 핵심 정리

  1. 실행 환경 — Python·터미널·PATH가 맞아야 코드가 돌아간다. 오류 메시지는 원인 추적의 출발점이다.
  2. 파일 역할 구분 — .py는 로직, .csv는 데이터, .html은 화면. 한 파일에 역할을 섞지 않는 것이 유지보수에 유리하다.
  3. 웹은 구조 + 디자인 — HTML로 내용을 잡고, CSS로 브랜드(네이버 그린 등)와 레이아웃을 입힌다.
  4. AI는 도구 — Cursor 모드에 따라 질문·계획·구현·디버깅을 나누면 작업 효율이 올라간다.
  5. 연동 설정 — MCP처럼 외부 연동은 설정 파일 문법과 환경(망, 경로)을 함께 봐야 한다.

오늘 실습을 통해 「코드를 실행한다 → 데이터를 다룬다 → 화면을 만든다 → AI·외부 도구와 연결한다」는 흐름을 한 번씩 경험했다.
